# sed2 0.1.0

First tagged version of the `sed2` prototype.

## Data model

- `Workflow` as the document, holding its tasks in a mapping and validating on
  construction that every `#task.port` reference resolves
- `Task` with the concrete types `modelImport`, `explicitODESimulation`,
  `report` and `dataRead`, joined in the `AnyTask` discriminated union so that a
  document round trips through json as the classes it was built from
- `Data` as the port value, holding either a literal or a reference, with
  `None` dropped from the serialization

## Task registry

- abstract `TaskDefinition` entries in `src/sed2/registry/definitions.py`,
  generated into `src/sed2/registry/repository.json`
- `PortSchema.datatype` is a string. It was annotated as the empty `DataType`
  stub, which made `python -m sed2.registry.definitions` fail with a validation
  error

## Execution

- a dagster backend implementing `dataRead`, both as a dagster op and as a plain
  function taking the task object
- a streamlit workflow builder driven by the registry

## Project

- documentation site built with zensical, published to
  [matthiaskoenig.github.io/sed2](https://matthiaskoenig.github.io/sed2),
  including the API reference and the `llms.txt` files for agents
- ruff, ty, pytest and the zensical build as required checks in continuous
  integration
- the two branch model with `develop` and `main`, enforced by repository
  rulesets in `.github/rulesets/`
